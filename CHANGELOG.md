# Changelog

All notable changes to this project are documented in this file. From 2.0.0 on,
entries are generated by [release-please](https://github.com/googleapis/release-please)
from [Conventional Commits](https://www.conventionalcommits.org/).

## Unreleased

### ⚠ BREAKING CHANGES

- WebGL1 is no longer supported; `Renderer` requires a WebGL2 context
- `Mesh` no longer owns GL state: `init`, `enableAttribs`, `disableAttribs`, `draw`, `updateBuffer`, `updateBuffers`, `recompile`, `setUniforms` and `dispose` are removed; the constructor no longer takes a `bufferUsage` (set `attribute.dynamic = true` instead)
- `Texture.upload`, `Texture.update` and `Texture.dispose` are removed; the renderer uploads textures when they are first used as a uniform. `TextureOptions.textureIndex` is removed; texture units are assigned by the renderer
- `material.uniforms` is a plain object, no longer a Proxy that writes through to GL. `wrapUniforms` is removed; `setUniform` takes a `WebGL2RenderingContext`
- Built-in shaders use GLSL ES 3.00 (`#version 300 es`); user-written GLSL ES 1.00 shaders keep working
- `createSphereGeometry` returns an indexed geometry
- Published JavaScript targets ES2022 (native class fields); Node 24 is required for tooling

### Features

- **renderer:** the renderer owns all GPU resources. Programs are cached per material (one program shared by all meshes using it), vertex array objects and buffers per geometry, textures per `Texture`
- **renderer:** attribute locations are fixed by name (`position` = 0, `normal` = 1, `uv` = 2, custom attributes in order of first appearance), so one VAO works with every program and no `layout()` qualifiers are needed
- **renderer:** uniforms are diffed and uploaded per draw; the setter is chosen from the type declared in the shader, so a `Vector` works for `vec2` and `ivec2` alike
- **renderer:** `renderer.dispose(geometry | material | texture)` frees the resources of a single object; `renderer.dispose()` frees everything
- **geometry:** `BufferAttribute.needsUpdate` re-uploads changed data via `bufferSubData`; `BufferAttribute.dynamic` hints `DYNAMIC_DRAW`; `BufferGeometry.version` tracks structural changes
- **texture:** `Texture.needsUpdate` re-uploads a changed image (video or canvas textures); mipmaps are generated for mipmap filters
- **material:** `DrawMode` constants (`DrawMode.TRIANGLES`, `DrawMode.LINES`, ...)
- **ci:** lint, test and build on branches and pull requests; docs deployed via `actions/deploy-pages`; releases via release-please and npm trusted publishing

### Bug Fixes

- `Vector` uniforms were routed through the integer setters (`uniform2iv` etc.), truncating floats
- `createPlaneGeometry` computed face indices with the row stride instead of the column stride and produced wrong triangles unless `rows === cols`
- shader compile and link errors are thrown as `Error` instances with the info log instead of bare strings

## [1.0.0](https://github.com/learosema/magic-pixels/releases/tag/v1.0.0) (2021-05-28)

Initial release, continuing the [colorful-pixels](https://github.com/sinnerschrader/colorful-pixels) library under a new name.

### Features

- `Renderer` rendering an array of `Mesh`es (WebGL1)
- `Mesh` combining a `BufferGeometry` and a `Material` (raw shader material with uniforms, vertex and fragment shader, draw mode)
- `BufferGeometry`/`BufferAttribute` with a three.js-like API; plane, box and sphere geometries; `mergeGeometries` and `createIndexedGeometry`
- `Texture` with filter and wrapping options, `Texture.fromImageUrl`
- `Vector`, `Matrix`, `Mat2`, `Mat3`, `Mat4`, `Color` helpers; `ortho`, `frustum`, `perspective` projection matrices; `Camera` with look-at
- `Stopwatch`, `mix`, `clamp` utilities
- API documentation generated with typedoc
